You are the lead creative developer, Three.js engineer, interaction designer, and frontend architect for a premium interactive website.

Your task is to BUILD a complete working proof-of-concept for a cinematic, scroll-driven 3D homepage for:

IP.NET SECURITY & LOCKSMITH

This is a real security, access control, low-voltage, networking, CCTV, intercom, and locksmith company serving New York City.

The purpose of this project is to create a premium, cinematic website experience where the visitor scrolls through one luxury New York building and discovers the different systems installed throughout the property.

Do not create a generic corporate website.

Do not create a typical hero section followed by cards.

The homepage itself must feel like an interactive architectural film controlled by scrolling.

The final visual direction should eventually feel comparable to a high-end digital agency / Awwwards-style interactive experience.

However, for this first implementation, prioritize:

1. Architecture
2. Scroll mechanics
3. Camera choreography
4. Scene transitions
5. Code quality
6. Performance
7. Easy replacement of placeholder 3D assets later

Do NOT stop because final 3D models are unavailable.

Create procedural / primitive placeholder geometry wherever required so the complete experience works immediately.

==================================================
PAGE BEHAVIOR
==================================================

The 3D experience should occupy the viewport while the user scrolls through a long scroll container.

Use ScrollTrigger with scrub.

The WebGL canvas should remain pinned/sticky while the overall scroll progress drives:

- camera position
- camera rotation
- object animation
- doors
- lighting
- opacity
- cable/system highlighting
- scene-specific UI text

Create one normalized master progress value:

0.0 → 1.0

Map all scenes to that master progress.

Approximate scene ranges:

0.00 – 0.08 INTRO
0.08 – 0.20 CCTV
0.20 – 0.31 INTERCOM
0.31 – 0.43 ACCESS CONTROL
0.43 – 0.54 LOBBY
0.54 – 0.67 NETWORK TRANSITION
0.67 – 0.78 NETWORK ROOM
0.78 – 0.86 WIRELESS
0.86 – 0.94 LOCKSMITH
0.94 – 1.00 FINAL PULLBACK

Do not use hard jumps between scenes.

Blend smoothly.

Use easing sparingly because scrub must remain responsive to scroll.

CAMERA SYSTEM
==================================================

Do NOT manually animate camera movement with dozens of arbitrary conditionals.

Build a clean camera choreography system.

Recommended approach:

Create named camera waypoints:

START_EXTERIOR
CCTV_CLOSEUP
INTERCOM_CLOSEUP
ACCESS_READER
DOOR_ENTRY
LOBBY
NETWORK_XRAY
NETWORK_ROOM
WIRELESS
LOCKSMITH
FINAL_PULLBACK

Each waypoint should contain:

position
lookAt target
optional FOV

Interpolate between waypoints based on normalized scroll progress.

Use smooth interpolation.

Rotation should remain controlled using lookAt targets or quaternions.

Avoid camera flips.

Avoid sudden FOV changes.

The route should feel intentional and cinematic.

Create a camera-debug mode available via query parameter:

?debug=1

Debug mode should display:

- current scroll progress
- current scene
- waypoint markers
- camera coordinates
- lookAt coordinates

This will make future tuning much easier.
